# Эксперимент: FastMCP 4 вместо MCPServer

[English](FASTMCP_EXPERIMENT.en.md)

## Предмет

Изолированная ветка `experiment/fastmcp-v4` основана на
`integration/mvp-review-2026-11-06` (черновой PR #15).
Сравнение проводится между **официальным MCP SDK 2.3.0 как сервером**
и **FastMCP 4.1.6 как сервером**. Сам стандарт MCP при этом не меняется.
FastMCP опирается на официальный стек MCP v2; импорт
`mcp.types.ToolAnnotations` остаётся действующим.

## Минимальная миграция

- Только `MCPServer` → `FastMCP` и зависимости в `pyproject.toml`.
- Все шесть имён инструментов, обязательные параметры, ответные словари,
  аннотации read-only/side-effect и точка входа `synplify-mcp`
  сохранены. Транспорт — локальный `stdio`, без HTTP-портов.
- `diagnostics.py`, `srr.py`, `metrics.py`, `compare.py`,
  `approved_run.py` оставлены без изменений; безопасность нельзя
  делегировать фреймворку.
- Внутрипроцессные проверки используют `fastmcp.Client` с
  `list_tools_mcp/call_tool_mcp`, а subprocess `stdio` проверяется
  независимо официальным `mcp.Client`.

## Контроль качества и критерии принятия

1. Реальная матрица Windows/Linux × Python 3.11/3.13/3.15.2
   должна пройти целиком, без пропусков протокольных тестов.
2. Должны совпадать шесть публичных имён и обязательные поля
   `inputSchema`, режимы read-only и побочных эффектов.
3. Отрицательные проверки должны отклонять неожиданные параметры
   (`command` и др.), а не интерпретировать их.
4. Независимый официальный MCP-клиент должен подтвердить
   `tools/list`/`tools/call` по `stdio`. Вызов
   `run_approved_synthesis` при выключенном флаге обязан
   возвращать `DISABLED`, без запуска процесса.
5. Никакие результаты по синтетическим отчётам не означают
   `EDA_PASS`: коммерческий Synplify и FPGA не тестировались.
6. Принять миграцию можно лишь при оправданном росте
   зависимостей и сохранении поведения. Модульность и middleware
   важны для будущего, но сами по себе не обязывают менять SDK.

## Оставшиеся риски

- Два основных пакета Python (`fastmcp` и `mcp`) прямо
  зафиксированы; зафиксированного и проверенного `uv.lock`
  пока нет. Часть зависимостей разрешается при установке.
- Из-за строгой валидации FastMCP неожиданные поля раньше
  могли игнорироваться, а теперь отклоняются; это намеренное
  ужесточение контракта, а не эквивалентность байт-в-байт.
- Одобренный `.prj` может исполнять вложенный Tcl; SHA-256
  защищает только файл проекта, не все его зависимости.
  Необходимы доверенная VM/учётная запись и контроль доступа.
- Включение HTTP-транспорта, middleware с внешними обращениями
  или proxy не входит в эксперимент. Безопасность локального
  `stdio` и отсутствие телеметрии сохраняются.

Документация FastMCP:
[переход с MCP SDK v2](https://gofastmcp.com/getting-started/upgrading/from-mcp-sdk-v2),
[встроенный клиент и тестирование](https://gofastmcp.com/clients/client).

Экспериментальное изменение не вносится в `main` и не
сливается в PR #15 без отдельного решения владельца.

## Результаты воспроизводимого эксперимента (6 ноября 2026)

| Проверка | MCPServer (PR #15) | FastMCP 4.1.6 |
| --- | --- | --- |
| Матрица ОС/версий Python | Windows/Linux × 3.11/3.13/3.15.2: 6/6 | Windows/Linux × 3.11/3.13/3.15.2: 6/6 |
| Количество unittest на конфигурацию | 79 | 80, добавлен тест строгой валидации |
| MCP-клиент для `stdio` | Официальный SDK 2.3.0 | Тот же официальный SDK 2.3.0 |
| Разрешённые зависимости (`uv sync`, Linux/3.13) | 31 пакет | 65 пакетов |
| Установленные зависимости (Linux/3.13) | 29 пакетов | 63 пакета |
| Полноценный лицензионный Synplify | NOT_RUN | NOT_RUN |

**Источники:** [исходная интеграция](https://github.com/chinn-choppa/synplify-mcp/actions/runs/42203127472),
[эксперимент FastMCP](https://github.com/chinn-choppa/synplify-mcp/actions/runs/42213862834).
Количество пакетов взято из `uv sync` в двух заданиях
`unit (ubuntu-latest, 3.13)`. Увеличение — **+34 пакета**.
Время выполнения тестов в CI не следует использовать как сравнимый
бенчмарк скорости фреймворков: тесты немного различаются, а машины
и кэши не контролируются.

**Предварительное решение:** совместимость подтверждена, но
для сервера с шестью операциями функциональное преимущество FastMCP
пока невелико по сравнению с ростом зависимостей. Экспериментальный
PR оставить черновым; перед массовым переходом оценить реальную
необходимость middleware/композиции и возможность сокращения
зависимостей при использовании `fastmcp-slim` с необходимыми extras.
