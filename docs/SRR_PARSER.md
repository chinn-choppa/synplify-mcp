# Парсер отчётов .srr (M2 / #4)

[English](SRR_PARSER.en.md)

Операция `parse_srr(relative_path, encoding="auto", limit=200)` читает **только**
файл `.srr` внутри настроенного оператором каталога. Она не запускает
Synplify, не открывает сеть и не выполняет Tcl.

Перед запуском сервера оператор задаёт абсолютный доверенный каталог:

```bash
export SYNPLIFY_MCP_WORKSPACE="/absolute/path/to/workspace"
uv run synplify-mcp
```

PowerShell:

```powershell
$env:SYNPLIFY_MCP_WORKSPACE = "D:\projects\authorized-workspace"
uv run synplify-mcp
```

В MCP-клиент передаётся **относительный** путь (с разделителями `/`):
`reports/build.srr`. Абсолютные пути, `..`, ссылки вне каталога,
суффиксы кроме `.srr` и файлы более 1 МиБ отвергаются. Чтение ограничено
по числу строк, диагностик и суммарному размеру JSON-диагностик (64 КиБ). Каталог должен быть
предварительно доверен; программа не является изоляцией от локального
злоумышленника, способного одновременно менять дерево файлов.

## Контракт результата

- `state="PARSED"` означает **только** успешное чтение и обработку файла.
  `synthesis_status="UNKNOWN"` всегда, пока нет проверки завершения EDA.
- `parse_health`: `PARSED`, `PARTIAL`, `EMPTY`,
  `NO_DIAGNOSTICS` или `UNRECOGNIZED`.
  Отсутствие сообщений не означает успешный синтез.
- При ошибке: `state="ERROR"`, `error_code` из фиксированного словаря
  (`INVALID_PATH`, `WORKSPACE_NOT_CONFIGURED`, `TOO_LARGE`,
  `DECODE_ERROR`, `SYMLINK_DENIED` и др.).
- Каждое сообщение содержит исходную строку `raw`, её физический номер
  `report_line`, байтовое смещение `byte_offset`, раздел `section`,
  уровень, код (или `null`), необязательное расположение в RTL и категорию.
- `report_sha256`, `encoding`, `size_bytes` позволяют привязать
  результат к конкретному файлу. `tool_version` и `device` равны
  `null`, когда надёжных сведений нет.
- `resources.state="NOT_EXTRACTED"`; `timing.state="NOT_EXTRACTED"`.
  Анализ ресурсов/timing — отдельная задача #5. Timing Synplify является
  предварительной оценкой, **не** post-place-and-route характеристикой.

Поддерживается UTF-8, UTF-8 с BOM, UTF-16 LE/BE с BOM; Windows-1252
только при явном `encoding="cp1252"`. При повреждении кодировки —
ошибка, не замена символов. Фикстуры искусственные, версии Synplify
не подтверждены реальным запуском.

**Конфиденциальность:** исходные сообщения RTL и строки журнала в
ответе MCP могут быть переданы клиентом внешней модели. Подключайте
закрытые проекты только к разрешённому локальному/корпоративному клиенту.
