# Процедура экспериментального выпуска

[English](RELEASE_PROCESS.en.md)

## Порядок

1. Провести ревью release PR; интегрировать #15 и фикс #14 **один раз**. Не включать эксперименты FastMCP #16 и #17.
2. Проверить зелёный CI на финальном коммите: Windows/Linux × Python 3.11/3.13/3.15; wheel/sdist в отдельных чистых окружениях.
3. Проверить `uv.lock`, `uv sync --locked`, `uv build`, `python scripts/verify_release_artifacts.py`.
4. Вручную проверить GitHub Private Vulnerability Reporting с правами владельца; исключить из артефактов лицензии, закрытый RTL и секреты.
5. **После одобрения владельца** слить release PR в `main` и создать тег `v0.1.0a1` на проверенном коммите. Тег пока не создан.

## Автоматизация

Workflow `.github/workflows/release.yml` запускается **только** по тегу `v0.1.0a*`. Проверяет совпадение тега с `pyproject.toml`, lockfile, тесты и установку wheel/sdist, затем создаёт **GitHub prerelease**, прикладывая оба пакета. Он **не публикует на PyPI** и не создаёт тег самостоятельно (`--verify-tag`).

## Ограничения

Alpha подтверждает MCP-протокол и обработку синтетических отчётов, не лицензионный Synplify. `run_approved_synthesis` по умолчанию отключён; утверждённый `.prj` содержит Tcl. До стабильного релиза необходима вендорская приёмка на реальных версиях и устройствах (`EDA_PASS=NOT_RUN`).
