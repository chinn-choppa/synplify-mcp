# Каталог форматов отчётов Synplify Pro (исследование M1)

[English](REPORT_FORMATS.en.md)

## Границы исследования

Эта работа опирается на **общедоступные ссылки** на справочные документы
Synplify Pro (разные редакции/годы) и на существующие открытые проекты.
Встроенные исходники, текст лицензированных руководств и реальные отчёты
Synopsys не копировались. Публичные фикстуры составлены с нуля и **не**
подтверждают поддержку конкретной версии Synplify.

| Источник | Наблюдаемая семантика | Что НЕ следует предполагать |
| --- | --- | --- |
| [Synplify Pro 7.0, 2001](https://www.arl.wustl.edu/projects/fpx/cse535/resources/synpro_ref_1001.pdf) | .srr как общий журнал компилятора и синтеза | единый состав секций у новых продуктов |
| [Microsemi Reference, 2020](https://ww1.microchip.com/downloads/aemdocuments/documents/FPGA/swdocs/synopsys/fpga_p201903asp1_reference_2019_03.pdf) | разделы компилятора, mapper, resource usage и START TIMING REPORT | наличие timing после compile-only; стабильные имена ресурсов |
| [Microchip Reference, 2021](https://ww1.microchip.com/downloads/aemdocuments/documents/FPGA/swdocs/synopsys/fpga_reference_R2021_03M_2021_03.pdf) | отдельный timing report, описание строк ресурсов | применимость структуры к любым семействам |

Руководства Synopsys могут иметь ограничения на воспроизведение.
Мы сохраняем только ссылки и собственное техническое описание, **без**
цитирования больших фрагментов, таблиц или скриншотов производителя.

## Модель разнообразия

- Текстовые диагностические сообщения: `@E:`, `@W:`, `@N:`, `@I:`
  (не все префиксы гарантированно встречаются в каждой редакции).
  После префикса может присутствовать код, путь и номер строки, или только текст.
- Пути бывают POSIX/Windows, с пробелами и скобками. Точное наличие
  колонки и положение кода являются необязательными.
- Разделы могут называться `START TIMING REPORT` или
  `START OF TIMING REPORT`, а содержимое секций меняется.
  При compile-only timing и utilisation могут отсутствовать.
- Типы и доступность LUT, регистров, блоков памяти, буферов, DSP и
  специализированных ячеек зависят от устройства и инструмента.
- Частоты `MHz`, периоды `ns` и slack `ns` нельзя без
  контекста ограничений сравнивать с post-route timing; неизвестные
  единицы/частоты должны быть `null`, а не `0`.
- Локальная кодировка журнала может отличаться от UTF-8:
  BOM UTF-8/UTF-16 и явно выбранная Windows-1252 подлежат проверке.
  Без достоверного определения кодировки нельзя терять байты с `errors="replace"`.

## Публичный корпус фикстур

Все файлы `tests/fixtures/srr/` **самостоятельно придуманы** для этого проекта.
Они не были получены запуском коммерческого Synplify.

| Файл | Назначение |
| --- | --- |
| `basic.srr` | префиксы сообщений без кодов; классические строки с путём |
| `sections.srr` | секции компилятора/timing/resource, условные DEMO-коды, latch/black box |
| `windows.srr` | CRLF и путь с Windows-диском |
| `truncated.srr` | оборванный отчёт без конца timing |
| `unrecognized.srr` | текст, который нельзя считать успешно разобранным |
| `empty.srr` | нулевой размер |
| бинарные и превышающие лимит | генерируются тестами, не хранятся в Git |

Коды `DEMO*`, имена FPGA и значения искусственные; совпадение с
реальными диагностическими кодами/версиями случайно. Классификация
форматов — **эвристика**, а не гарантия совместимости.

## Пределы M1

Задача #3 устанавливает исследовательскую базу, но не подтверждает
поддержку Synplify 2001/2020/2021/2024 и не проверяет Windows/Linux EDA.
Следующий этап #4 — защищённый парсер с `parse_health`, происхождением
исходных строк и состояниями отсутствующих данных; #5 — отдельная
версионированная нормализация ресурсов и timing.
