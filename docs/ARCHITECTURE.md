# Архитектура

## Роли компонентов

```text
MCP-клиент (Codex / Claude / OpenCode / др.)
           |
      MCP stdio
           |
  synplify_mcp.server
     |           |
   runtime    diagnostics + srr
   (поиск)    (текст + .srr)
           |
 Synopsys Synplify Pro (в будущих версиях)
```

По умолчанию сервер только читает отчёты `.srr` из заданного workspace. Экспериментальный запуск утверждённых оператором проектов `.prj` включается отдельно, без произвольных аргументов shell/Tcl. При этом `.prj` сам может содержать исполняемый Tcl и требует доверенного окружения; см. [руководство запуска](APPROVED_RUN.md). Добавление исполнителя допускается только после выделения узких, проверяемых операций, а не универсального `run_command`.

## Почему отдельный репозиторий

- Сервер развивается и выпускается независимо от навыков и установщика `agent-dev-toolkit`.
- `agent-dev-toolkit` впоследствии может устанавливать определённую версию из доверенного реестра; обратной зависимости нет.
- Публичный интерфейс MCP должен работать с любым совместимым клиентом, не только с Codex.
- Повторно используемый код между тремя EDA-адаптерами можно извлекать **после** появления как минимум двух проверенных сценариев.

## Изоляция и воспроизводимость

По умолчанию локальный stdio, без внешнего HTTP и сетевых запросов. Входные и выходные каталоги будущих EDA-операций должны задаваться явно. Каждая операция обязана фиксировать tool/version, конфигурацию сборки, полный exit status, артефакты и статус `NOT_RUN` при пропуске реального выполнения.

## Недопустимые сокращения

Ни `--version`, ни `tools/list`, ни успешная компиляция Python не подтверждают корректность RTL. Обнаруженный бинарник ещё не означает проверенную конфигурацию лицензии. Не объявлять testcase `PASS` только по отсутствию ошибок в текстовом выводе, если не установлен надёжный критерий завершения.

## Предметный сценарий

Готовый отчёт .srr → структурированные ошибки/предупреждения → сравнение сборок; активный синтез только после отдельной реализации защищённого исполнителя.

## Полная композиция прототипа

Шесть инструментов: `server_info`, `tool_status`, `parse_diagnostics`, `parse_srr`, `compare_srr_reports` (чтение) и `run_approved_synthesis` (побочные эффекты, по умолчанию отключён). `server_info` отдельно сообщает, есть ли техническая реализация запуска, включена ли она оператором и проверена ли на реальном EDA.

Режим `-batch` может выполнять встроенный Tcl из доверенного .prj. Даже фиксированный список аргументов **не** заменяет проверку вложенных файлов и изоляцию ОС. Сопоставление timing не выдаёт дельты без доказательства равенства полных временных ограничений. [Запуск](APPROVED_RUN.md), [сравнение](COMPARE.md).
