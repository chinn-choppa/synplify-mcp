# synplify-mcp

[English](README.en.md) · [Участие в разработке](CONTRIBUTING.md) · [Безопасность](SECURITY.md)

Локальный MCP-сервер для анализа синтеза FPGA и отчётов Synopsys Synplify Pro.

> **Статус: bootstrap / экспериментальный (0.0.1).** Проект содержит проверяемый каркас MCP, безвредное обнаружение установленного инструмента и ограниченный разбор текстовых диагностик. По умолчанию он **не запускает** синтез или симуляцию; экспериментальный запуск строго утверждённых проектов возможен только после отдельного включения оператором и не подтверждает корректность коммерческих инструментов. См. [план](docs/ROADMAP.md).

## Для чего нужен

Сопоставление предупреждений синтеза, ресурсов и предварительных временных отчётов между сборками.

**Принципы:** отдельно от `agent-dev-toolkit`; свободная установка из исходников; никаких встроенных EDA-бинарников, лицензий, облачных запросов и непрошеных изменений файлов проекта. Каждая команда имеет ограниченную область доступа и возвращает наблюдаемые доказательства, а не догадки.

## Быстрый старт

Нужен Python 3.11+ и установленный `uv`. Для самого MCP-сервера нужен совместимый MCP SDK v2.3.0; SDK будет установлен в локальное виртуальное окружение при выполнении `uv sync`.

```bash
git clone https://github.com/chinn-choppa/synplify-mcp.git
cd synplify-mcp
uv sync
uv run synplify-mcp
```

Локальная конфигурация клиента MCP (пример структуры; конкретный путь к `uv`/проекту и формат конфигурации зависят от клиента):

```json
{
  "mcpServers": {
    "synplify-mcp": {
      "command": "uv",
      "args": ["--directory", "/absolute/path/to/synplify-mcp", "run", "synplify-mcp"]
    }
  }
}
```

Это пример для клиентов с ключом `mcpServers`; Codex и OpenCode используют собственные схемы. Все пути должны указывать на доверенную локальную копию.

## Доступные инструменты прототипа

| Tool | Назначение | Граница |
| --- | --- | --- |
| `server_info` | Идентификатор сервера, состояние, ограничения | Только чтение |
| `tool_status` | Поиск установленного `synplify_pro` или пути из переменной `SYNPLIFY_MCP_EXECUTABLE` | Не запускает EDA-продукт |
| `parse_diagnostics` | Выделение диагностических сообщений из переданного текста | До 1 МиБ и 200 записей |
| `parse_srr` | Чтение `.srr` в разрешённом каталоге с байтовыми смещениями и диагностикой ошибок | До 1 МиБ входа и 64 КиБ диагностик; без запуска EDA |

Экспериментальный парсер извлекает только подтверждённые диагностические сообщения и структуру отдельных разделов. Полный разбор ресурсов/timing и запуск синтеза запланированы отдельно.

## Воспроизводимые проверки

```bash
python -m unittest discover -s tests -v
python -m compileall -q src tests
```

После `uv sync` проверьте запуск `uv run synplify-mcp` с MCP Inspector или настоящим MCP-клиентом. Одна лишь установка или `tools/list` **не доказывает** успешное выполнение EDA-команды. Протокольные тесты CI проверяют реальные MCP-вызовы. Статус коммерческого Synplify и полноценного синтеза остаётся `NOT_RUN`.

## Чтение .srr (экспериментальная функция)

Инструмент `parse_srr` читает только разрешённый оператором каталог через `SYNPLIFY_MCP_WORKSPACE`. [Безопасность и контракт парсера](docs/SRR_PARSER.md). Наличие ошибок/их отсутствие не подтверждает результат синтеза.

## Метрики ресурсов и предварительный timing

В задаче #5 добавлен консервативный разбор явных подписанных разделов ресурсов и временных оценок. Неизвестные значения сохраняются как `null` с диагностикой неоднозначности; оценки Synplify **не** равны post-route timing. [Контракт метрик](docs/METRICS.md).

## Экспериментальный запуск утверждённых проектов

Команда `run_approved_synthesis` (#6) по умолчанию отключена. Она требует операторский список проектов и сверяет SHA-256 `.prj`; не принимает произвольный Tcl/shell. Проект может сам выполнять Tcl, поэтому это **не песочница**. Нулевой код завершения не считается успешным синтезом. [Руководство и ограничения](docs/APPROVED_RUN.md).
